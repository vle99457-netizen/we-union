# Web Design Orchestrator

Use the installed skills as a pipeline rather than as competing instructions.

## Core sequence

1. **Karpathy discipline first** — apply `karpathy-guidelines` throughout: understand the request, keep scope surgical, prefer simple solutions, and verify the result.
2. **Design system** — use `ui-ux-pro-max` to determine page pattern, typography, color system, spacing, component behavior, accessibility requirements, and stack-specific guidance.
3. **Art direction** — use `design-taste-frontend` to strengthen hierarchy, composition, imagery, typography, motion, and brand distinctiveness while avoiding generic AI-looking layouts.
4. **Implementation** — build with the project's existing stack. Preserve routes, backend behavior, data contracts, and working features unless the request explicitly changes them.
5. **React Bits selectively** — use `reactbits-ui-skills` only when the project is React-compatible and a React Bits component clearly improves the experience. Prefer a small number of purposeful components over decorative overload. Verify dependency, accessibility, performance, mobile behavior, and reduced-motion support before adding one.
6. **Design cleanup** — use `impeccable` to audit, normalize, distill, and polish the implemented interface. Fix high-impact anti-patterns and inconsistencies instead of blindly applying every stylistic suggestion.
7. **Final web audit** — use `web-design-guidelines` for accessibility, responsive behavior, interaction states, forms, semantics, navigation, and web best practices. Resolve important findings before completion.

## Conflict resolution

- Project requirements and existing functionality outrank aesthetic preferences.
- Accessibility and usability outrank animation or novelty.
- Performance outranks unnecessary visual effects.
- When two design skills disagree, prefer the choice that best matches the brand brief and user task, then verify it in the final audit.
- Do not install a component library or add a dependency merely because a skill mentions it.

## Delivery checklist

- Existing functionality preserved unless intentionally changed.
- Clear visual hierarchy and coherent design system.
- No generic AI template look or excessive card nesting.
- Responsive at mobile, tablet, laptop, and large desktop sizes.
- Keyboard/focus states and accessible contrast verified.
- Motion is purposeful and respects reduced-motion preferences.
- No obvious unnecessary dependency or bundle-cost increase.
- Final audit findings addressed.
